## 1. 验证一：前台服务内独立 Flutter 引擎的后台解析

### 结论：**可行** ✅（真机已确认）

**真机日志（小米 10 Lite Zoom / Android 12）**
```
BG isolate up
ParserManager ready: 1.2.0 (内置)
COOKIES xhs=true ig=true x=false len=1022 (NON-EMPTY)
PARSE OK (1854ms) xhs "wow～ 好干净的奶白色" items=1 :: https://xhslink.cn/o/AzXyjFXn99
PARSE OK (7857ms) instagram "" items=6 :: https://www.instagram.com/p/DeB9MBxG_sX/...
PARSE OK (355ms)  x   "" items=1 :: https://x.com/eric_sayompoo/status/2111025862892269612
VALIDATION DONE
```

**结论说明**
- 无 Activity 的独立 `FlutterEngine` 里，`HeadlessInAppWebView` **正常工作**：三条链接（含短链、IG 多图、X）全部解析成功。
- **Cookie 共享成功**：后台引擎读到与主 App 登录一致的 cookie（xhs=true / ig=true，header 非空 1022 字节）。原因：同进程下底层就是进程级 `android.webkit.CookieManager` 单例。
- 性能可接受：XHS 1.8s（短链跳转）、X 0.35s、IG 7.8s（首次加载较慢，可后续优化）。

**遗留问题 / 风险**
- 必须与主 App **同进程**（默认即可）。若将来把后台引擎放 `:remote` 独立进程，cookie 单例不再共享，需改为落盘传递。
- IG 首次解析 7.8s 偏慢（Headless WebView 冷启动 + 页面加载），正式实现需加"解析中"状态与超时。
- 多引擎占内存，解析结束及时 `engine.destroy()`。

## 2. 验证二：透明 Activity 读取剪贴板

### 结论 2a：「剪贴板变化 → 绿点」**不可行** ❌（真机已确认）
- 真机：复制链接后**悬浮球没有出现绿点**。根因：Android 10+ 的 `OnPrimaryClipChangedListener` 只在**前台应用/默认输入法**收到回调，后台服务收不到。
- 处理：**去掉绿点功能**，改为**点击时才读取剪贴板**。已同步更新 `roadmap.md` 与 `ui-spec.md`。

### 结论 2b：「点击 → 透明 Activity 读取剪贴板」**有条件可行** ⚠️
- 真机：**不闪烁** ✅、**小红书视频没有被暂停** ✅、**出现系统粘贴提示** ✅；但 **CLIPBOARD 读到 `<null>`（被判定为空）** ❌。
- 根因分析：探针在透明 Activity 的 **`onCreate`** 里读剪贴板，此时窗口**尚未获得焦点**，Android 10+ 会拒绝返回内容（返回空）。真机出现"粘贴提示"说明系统认为发生过读取，但内容为空。
- **修复方向**：在 `onResume` / `onWindowFocusChanged(hasFocus=true)`（即窗口获得焦点后）再读，读完立即 `finish`。**需按此再真机复测一次。**
- 备选（若 MIUI 仍拦截）：
  1. 用**可获焦点的 overlay 窗口**（`TYPE_APPLICATION_OVERLAY`，读取时临时申请焦点）读剪贴板，完全不启动 Activity；
  2. 引导用户在**主 App 内**粘贴（首页已有"自动检测剪贴板"，天然在前台，最稳）。
- 注意：读取需处理 Android 12+ 剪贴板敏感内容标记（`ClipDescription` 的敏感 flag）。

## 3. 验证三：悬浮窗里的"选择下载"面板方案对比

### 结论：**两者皆可行；最终定为"复用后台引擎的 FlutterView"** ✅

- 真机：原生面板"正常显示并可点击" ✅（`Native selection panel shown`）。
- 对比：

| 维度 | 原生 Kotlin 绘制 | FlutterView 挂悬浮窗 |
|---|---|---|
| 内存 | **低**：仅 overlay 窗口，无额外引擎 | 中：**复用后台已有引擎**，无需第三个引擎 |
| 开发量 | 中高：UI 手写；缩略图要接图片库并**手动带 Referer/UA 头** | **低**：复用现有九宫格面板与 `CoverImage`（含 Referer） |
| 风格一致 | 中：手工对齐 token，易漂移 | **高**：与 App 内完全一致 |
| 技术风险 | 低：单窗口，成熟 | 中：FlutterView 挂 `TYPE_APPLICATION_OVERLAY` + 输入分发 |

**定案（按你要求）**：选择面板**复用后台服务里已有的 Flutter 引擎**，把 **FlutterView 挂到悬浮窗**上，**不再创建第三个引擎**；悬浮球本身仍用原生 Kotlin。

## 4. 基于结论的完整实现方案（覆盖 roadmap v1.6 全部）

### 4.1 架构总览

```
┌─────────────── 三个入口 ───────────────┐
│ 分享到后台下载（透明 Activity 收文本） │
│ Quick Settings Tile（原生 TileService）│
│ 悬浮球 BubbleService（原生）           │
└───────────────┬────────────────────────┘
                │ 统一 → parse+download 任务
                ▼
      HostService（前台服务，原生，持有唯一后台引擎）
        ├─ 后台 FlutterEngine（后台 isolate）
        │    ├─ 解析：复用 parse_service（HeadlessInAppWebView）
        │    ├─ 下载：复用 DownloadManager
        │    └─ FlutterView → 挂到悬浮窗做"选择面板"（复用本引擎，不新建）
        ├─ MethodChannel 进度/结果 → 更新悬浮球 + 通知
        └─ 剪贴板：透明 Activity（获得焦点后读）
```

**核心原则**：三个入口**只负责"拿链接/文本 + 触发"**；解析与下载**全部复用**现有 `parsePostOutcome` 与 `DownloadManager`，产物写入 HistoryDb，与 App 内一致。

### 4.2 后台任务 Host（对应验证 1，可行）

- `HostService`（FGS，`foregroundServiceType="dataSync"`）持有**唯一**后台 `FlutterEngine`（复用验证 1 的创建方式：`FlutterEngine(ctx,null,true)` + `executeDartEntrypoint("backgroundMain")`）。
- MethodChannel `easysave/bgtask`：`submit(urls, mode)`（mode = all / select / caption / open）、进度回调、结果回调、`openPanel`（把 FlutterView 挂到悬浮窗）。
- 解析/下载在 Dart 侧直接调用 `parsePostOutcome` 与 `DownloadManager`，进度经监听转发到原生。
- **引擎生命周期（统一，见 4.9）**：**有任务在跑或面板打开时保持存活**；**空闲 60 秒后销毁引擎并 `stopSelf`**。任务/面板期间 Dart 侧持续 `keepAlive`，结束后上报 `idle` 让服务重启 60s 计时。悬浮球是**原生**的，**不依赖引擎常驻**，引擎被销毁不影响悬浮球运行。
- **启动时机（避免 `ForegroundServiceStartNotAllowedException`）**：
  - **悬浮球入口**：已有"显示在其他应用上层"权限 → 可直接 `startForegroundService`。
  - **分享 / Tile / PROCESS_TEXT 类入口**：由**透明 Activity 在前台时**启动 HostService（此时 App 处于前台，允许启动 FGS）。
- 与主 App 共享 cookie。

### 4.3 悬浮球（原生，OverlayService）

- **开关与授权**：我的 → 设置 → 快捷入口 新增"**悬浮球**"开关（默认关）；开启时若 `!Settings.canDrawOverlays()` → 跳 `ACTION_MANAGE_OVERLAY_PERMISSION`，返回后（生命周期 `resumed`）复查并启动；启动成功后**一次性提示开启"自启动/后台运行"**（并提供"去设置"跳应用信息页），保证划掉 App 后能常驻。
- **权限撤销联动**：App 每次 `resumed`（以及首次进入「我的」）以**服务实际状态**为准对账开关（`BubbleService.isRunning()`）：权限被撤销或悬浮球已被关闭时，设置开关自动变关闭；反之服务在运行则显示开启。不再在启动时按持久化开关自动拉起（避免与服务结束互相打架、出现"关了又回来"）。
- **外观**：`OverlayService`（原生，前台服务 `specialUse`）用 `WindowManager` 添加渐变圆（`#FC494C→#FA662E`），可拖动、松手吸附最近左/右边缘，闲置 `alpha≈0.82`。**无绿点**（见 2a）。
- **点击**：经 `ClipboardReader`（前台透明页）读剪贴板 → 无链接 Toast"先在 App 里复制链接"；有链接向内侧展开**圆形菜单**（原生全屏 overlay：半透明遮罩 `#66000000`，四项图标沿气泡内侧排成弧形，点空白或再点气泡收起）。
- **菜单四项**：全部下载 / 选择下载（占位，提示"即将上线"）/ 复制文案 / 打开 EasySave。
  - 全部下载 → `HostService.submitText(mode=all, source=bubble)`，气泡显示"已完成/总数"。
  - 复制文案 → `HostService.submitText(mode=caption)`：解析后**经原生 `clipboard` 方法**写入剪贴板（headless 引擎无 `PlatformPlugin`，不能用 `Clipboard.setData`）并提示。
  - 打开 EasySave → 启动 `MainActivity` 带 `EXTRA_OPEN_URL` → Dart 切到解析页并 `_resolve` 进入该帖预览页。
- **进度 / 完成 / 错误态**：`HostService` 经 `bubble` 通道推送；进行中显示环形进度 + "done/total"，完成显示 ✓、失败显示 !（均 2.5s 后复位）。
- **拖到底部关闭区**：拖动时底部中央出现红色 ✕ 目标；松手落在其上 → 关闭气泡（`stopSelf`）并 Toast"可在设置中重新开启"、**广播 `ACTION_BUBBLE_STATE`**；MainActivity 在前台时把事件经 `easysave/bubble` 的 `bubbleStateChanged` 推给 Dart，「我的」页无需切换出去即可**实时**把开关置为关闭（加回到 App 时的 `resumed` 对账兜底）。
- **错误态点击进错误页**：错误态保持期间点气泡 → 用 `lastError`（url/code/message）打开 App 对应错误页（与错误通知同一路径）。
- **划掉 App 后存活（尽力而为）**：`onStartCommand` 返回 `START_STICKY`，并在 `onTaskRemoved` 用 `AlarmManager` 1s 后重启服务。MIUI 可能仍需用户开启"自启动/后台允许"。

### 4.4 快捷开关（Quick Settings Tile）

- `EasySaveTileService`（原生）：`label`="EasySave 下载"，图标用**单色线条图标**（系统会自动着色）；`onStartListening()` 更新磁贴态。
- **`onClick()` 关键点**：TileService **没有窗口焦点，不能直接读剪贴板** → 必须**启动 `ClipboardReader` 透明 Activity** 来读；读到链接后再由该 Activity 于前台启动 HostService（`mode=all`）。无链接时 Toast"剪贴板里没有可解析的链接"。
- **Android 14+**：`onClick()` 里用 `startActivityAndCollapse(PendingIntent)` 启动 `ClipboardReader`；**Android 13 及以下**用已弃用的 `startActivityAndCollapse(Intent)`。
- **激活态 / 进度**：下载进行中磁贴显示为**激活状态**，副标题显示进度（`Tile.subtitle`，Android 10+）；空闲时恢复。
- **「我的 → 设置 → 快捷入口」加"添加到控制中心"**：Android 13+ 调用 `StatusBarManager.requestAddTileService(...)` 直接弹系统确认框；Android 12 及以下显示图文说明（下拉控制中心 → 编辑 → 拖入"EasySave 下载"）。
- **空链接提示**：由 `ClipboardReader`（前台透明 Activity）弹出"剪贴板里没有可解析的链接"——前台 Activity 的 Toast 才不会被系统在后台拦截。
- **磁贴状态推送**：`HostService` 通过静态状态 + `TileService.requestListeningState` 触发 `onStartListening` 刷新磁贴；下载开始时激活并显示"已完成/总数"，结束或引擎销毁时复位为 INACTIVE。

### 4.5 剪贴板读取（统一下沉，含修复）

- 统一走 `ClipboardReader`：透明、无动画 Activity（复用验证 2 实现）。
- **关键修复**：在 `onWindowFocusChanged(hasFocus=true)` / `onResume` 后读剪贴板（真机 `onCreate` 读为空），读完 `finish`。
- 处理 Android 12+ 敏感内容标记；读取后立即返回文本给调用方做可解析链接判定（复用 `platformFromUrl`）。
- 若 MIUI 仍拦截：回退到 focusable-overlay 读取，或引导到主 App 内粘贴。

### 4.6 分享到 EasySave 后台下载（分享面板入口）

- `ShareToBackgroundActivity`：透明、无动画、`exported=true`，`intent-filter` 只接收 `ACTION_SEND`（`text/plain`），`label`="EasySave 后台下载"；**与现有打开 App 的分享入口（MainActivity 的 ACTION_SEND）并存**，两个入口都会出现在系统分享面板，行为各自独立。
- 流程：收到 `EXTRA_TEXT` → 抽链接（**Dart 侧用 `platformFromUrl`/`extractLinks` 做权威判定**；原生只做"是否含 http"的廉价预检以避免为空文本启动引擎）→ 从前台启动 HostService → **立即 finish，用户停留在原 App**。
- 无链接时 Toast"**没有可解析的链接**"（原生预检直接 Toast；含 http 但不受支持时由 Dart 回抛 `toast`）。
- 此入口文本由系统分享给出，**不依赖剪贴板读取**。
- **为什么取代 PROCESS_TEXT**：用户很少能直接选中完整链接；系统分享面板才是 IG / X / 浏览器的主要路径。PROCESS_TEXT 从 v1.6 移除，仅记入 `roadmap.md` 的"后续想法"。

### 4.7 下载链路复用

- 全部下载：`parsePostOutcome` → `DownloadManager.startBatch(post, 全部 index)`。
- 选择下载：解析后挂 FlutterView 面板 → 确认后 `startBatch` 选中项。
- 复制文案：解析后 `ClipboardManager.setPrimaryClip(标题+"\n"+正文)`，Toast。
- 打开 EasySave：`Intent` 启动 `MainActivity` 并携带参数跳到预览页。
- 所有批次终态写 HistoryDb（沿用现有逻辑）。

### 4.8 双引擎下的批次归属与并发（新增，重要）

主界面引擎（main isolate）与后台引擎（background isolate）是**两个独立 Dart 隔离区**，各自的 `DownloadManager`/`HistoryDb` 是**各自内存里的实例**，但底层**共享同一份原生资源**：background_downloader 的原生任务队列/DB、同一个 SQLite 文件、系统 MediaStore/相册。因此必须明确归属：

- **批次来源标记**：每个下载批次带 `source`（`main` / `background`），写进 background_downloader 的任务元数据（如 taskId 前缀 `bg:`/`main:`，或 DB 中的 `group`/自定义字段）。
- **职责单一**：**发起方引擎**独占负责该批次的终态处理——下载完成后的**相册落盘 + 写历史 + 通知/悬浮球状态**。**非发起方引擎忽略**非本来源的批次。
- **"启动时补存"恢复**：App/服务启动时的补存（reconcile/恢复未完成或已完成但未入库的任务）**只处理本来源的批次**（main 引擎只补存 `main:` 前缀，后台引擎只补存 `bg:`）。避免两个引擎对同一批次重复落盘/重复写历史。
- **幂等写入**：
  - 历史记录以帖子 id 为主键，写历史用 `INSERT OR REPLACE`/`ON CONFLICT DO UPDATE`；
  - 相册关联用"已存在即跳过"（`findDownloadedIndices` 先查再关联），保证重复执行不产生重复项。
- **SQLite 并发写入处理**：
  - 两个引擎各自持有 sqflite 连接访问**同一个 DB 文件** → 开启 **WAL 模式**（`PRAGMA journal_mode=WAL`）允许并发读 + 单写，并设置 `busy_timeout`（如 5000ms）在锁冲突时重试等待；
  - 所有写操作走**幂等语句** + 短事务，避免长事务持锁；
  - 不做跨 isolate 的 Dart 级互斥（不共享内存），依赖 SQLite 自身的锁 + 幂等约束保证不重复、不冲突。
  - 备选：若实测锁等待频繁，可把 HistoryDb 收口为**只由后台引擎写**（主界面通过 MethodChannel 代理写），彻底消除双连接写。
- **background_downloader 双引擎回调验证（实现前先做最小验证）**：主界面引擎开着时，后台引擎发起的下载，其**完成回调是否到达后台引擎、且是否只落盘一次**需实测。验证方式：主界面运行 + 后台引擎发起一次下载，观察两个引擎各自的完成回调与相册落盘次数。
  - 若回调**只到一个引擎**（插件回调绑定在注册任务的引擎上）：按需处理即可。
  - 若回调**可能到两个引擎**或不确定：改为**后台批次由 HostService 原生侧监听完成**（用插件在 Android 原生的 task 跟踪），或**用 background_downloader 的任务跟踪库对账**（以 taskId/来源为准，落盘与写历史幂等），确保只落盘一次、只写一次历史。
  - 验证结论写入本文件。

### 4.9 选择下载面板（原生 overlay）

- **改用原生 View 面板**：真机验证发现把 `FlutterView` 挂到 `TYPE_APPLICATION_OVERLAY` 在 MIUI 上不可靠（透明 `SurfaceView` 不出图、触摸无响应、遮罩不显示），因此改为**原生 Android View** 面板（`SelectPanelView`），与悬浮球/菜单一致的 overlay 技术，稳定可用。
- 悬浮球"选择下载" → `HostService.submitText(mode=select)`；Dart 解析成功后通过 `showSelectPanel` 把**缩略图列表**交给原生，原生用一个全屏 `TYPE_APPLICATION_OVERLAY` 窗口展示（顶部半透明蒙层 + 底部圆角卡片 + 三列缩略图网格）。
- **缩略图**：原生线程池用 `HttpURLConnection` 拉取，带 **webview `CookieManager` 的 Cookie** 与移动端 UA，避免小红书 CDN 因缺 Cookie 返回空图。
- **交互**：默认全选；点缩略图切换勾选（未选加暗层、选中显 ✓）；全选/取消全选；"下载(N)"；✕ 或点蒙层取消。
- **回传**：原生选中后调用 `channel.invokeMethod("selectResult", {indices})`，Dart 收到后 `startBatch(选中索引)` 并 `unmountSelectPanel`；取消回传 `null` 则不下载。
- **生命周期**：面板打开期间发 `keepAlive`；关闭后空闲计 60s 才销毁引擎。**不复用为渲染用（不新建、不给后台引擎挂 View）。**

### 4.10 「我的 → 设置」改动

- 新增分组"快捷入口"：**悬浮球开关**（含授权引导与撤销联动）、**"后台下载结果提示"开关**（控制后台下载的 Toast：准备 / 开始 / 结果）、"添加到控制中心"（Android 13+ 直接弹系统确认框，12- 图文说明）、剪贴板读取说明。

### 4.11 前台服务类型与合规（Android 14）

- `HostService` 解析+下载用 `dataSync`；悬浮球若判定特殊用途用 `specialUse` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`。
- 补 `FOREGROUND_SERVICE`/`FOREGROUND_SERVICE_DATA_SYNC`（已具备），视需要 `FOREGROUND_SERVICE_SPECIAL_USE`；通知栏常驻。

### 4.12 后台流程的权限与历史刷新（不弹权限框）

- **后台流程绝不弹权限框**：后台 isolate 里不调用任何会弹系统权限框的 API（`startBatch(requestGalleryAccess:false)` 只做无权限即抛出的判定）。
- **以实际写入是否成功为准**：Android 10+ 写入相册**无需权限**，撤销相册权限后后台下载照常成功，属正确行为——因此**不做**"预检 `Gal.hasAccess()` 就报未授权"的短路；只有在**真正写入失败**时才报错（错误/日志）。
- **读取权限提示（App 内）**：历史页 / 画廊在**无相册读取权限**时，顶部显示提示条"**授权相册访问后可显示缩略图**"，点击请求权限（含 Android 14 部分授权）。仅影响本地缩略图显示，不影响下载。
- **历史刷新联动**：后台引擎写入历史后（1）**若主界面正在前台**，经 `easysave/host` 反向通道实时通知它刷新历史页；（2）历史页在**生命周期 `resumed`**（例如从别处切回）时再次从 `HistoryDb` 重新加载。两条路径都保证切回即见新记录。

### 4.13 错误通知与错误页联动

- 后台解析失败时，通知通过 `HostService` 的 `error` 方法携带**原链接 + 错误码 + 错误信息**（PendingIntent extras）。
- 点击通知打开 `MainActivity`：**冷启动**读 `getIntent()`、**热启动**走 `onNewIntent`；`MainActivity` 把 extras 转交 Dart（`openParseError` 推送 + 启动时 `getPendingError` 拉取），并**清除 extras**，保证只消费一次、返回后再进不重复跳转。
- 主界面收到后切到解析页，显示与手动粘贴**相同**的错误页（含 `LOGIN_REQUIRED` 的"去登录"按钮）。
- **App 侧错误归类**：解析失败且错误码为 `PRIVATE_OR_UNAVAILABLE`、且该平台**当前无登录 cookie** 时，App 侧把错误改归类为 `LOGIN_REQUIRED`（提示"可能需要登录{平台}"），避免未登录小红书时误报"分享链接可能已过期"。**只在 App 侧做**，parser 与 `spec/fixtures` 不变；App 内手动解析同样适用。
