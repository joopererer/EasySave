# EasySave Roadmap

> 版本完成后勾选对应项：把 `- [ ]` 改为 `- [x]`。
> 每次只实现指令中指定的版本功能，不要提前实现后续版本。

## v1.1a 界面与本地能力

- [x] `ui-spec` 中的全部 UI 调整（见 `docs/design/ui-spec.md`）
  - 验收：首页/预览页/下载面板/历史页/"我的"页与 ui-spec §2 一致；无"原型版本"文字；深色模式下所有文字与背景对比度符合 Material 3 深色规范（无浅色残留）
- [x] 下载历史：本地数据库记录平台、作者、标题、缩略图、原帖链接、时间、文件数
  - 验收：断网可打开历史页；每条记录字段齐全；点击卡片可打开预览页
- [x] 设置页：相册名称（默认使用 App 名称）、文件名格式、同时保存文案为 txt、自动检测剪贴板开关、清除缓存、版本号
  - 验收：每项设置重启后保持；相册名称修改后新下载落到新相册；关闭自动检测后打开 App 不弹确认卡片
- [x] 复制文案：预览页可折叠文案区 + "复制文案"按钮（复制标题 + 正文）
  - 验收：复制文本为"标题换行正文"；无标题或无正文时不产生多余空行
- [x] 诊断信息：解析失败时可以复制平台、错误码、链接、App 版本；不能包含 cookie 或任何账号信息
  - 验收：复制文本含且仅含四项；全局搜索代码确认无 cookie 写入剪贴板/日志

## v1.1b 后台与重试

- [x] 后台下载 + 失败重试，用 `background_downloader` 包（通知栏按批次合并进度，切到后台时不中断；单个文件失败时 Manager 层换备用地址共试 3 次；仍失败的标红并可以单独重试；单个文件失败不导致整批报错）
  - 验收：下载中按 Home 键，通知栏进度持续更新；返回 App 进度无丢失；拔网 1 张后恢复，该张自动重试成功；3 次全失败时仅该行标红，其余文件正常落盘
  - 方案评估（实施前写进 PR 描述）：`background_downloader` 与现有 `gal` 直存链路的衔接方式（下载到沙盒再 `Gal.putImage/putVideo` 落盘，还是直接下载到相册目录）；通知栏 channel 与 App 名称；iOS 后台模式是否需要额外配置

## v1.1c 视频与 Live 预览

- [x] 视频和 Live 图全屏预览（`video_player` + 平台 Referer；真机未发现编解码问题，未引入 `media_kit`）
  - 先用 `video_player` 实现，通过 `VideoPlayerController.networkUrl` 的 `httpHeaders` 传入对应平台的 Referer；只有在真机上测出 `video_player` 无法满足的问题（例如编码不支持）时，才评估 `media_kit`，并说明原因和 APK 体积影响
  - 视频：全屏播放，带控制条；切到后台时暂停，离开页面时释放播放器
  - Live 图：默认显示静态图，长按播放 motion（静音、循环），松手停止
  - 验收：小红书视频、IG Reel、小红书 Live 图都能在预览页播放；连续切换 10 个视频后内存没有明显增长

## v1.2 分享与批量

- [x] 分享：把下载结果通过 Android 分享发给其他 App，附带原帖链接、作者、文案，用于和 UniPost 衔接
  - 验收：下载面板的 [分享] 可用；目标 App 收到图片和文本，链接、作者、文案齐全
- [x] 批量解析：一次粘贴多个链接，逐个解析并生成下载任务
  - 验收：粘贴包含 3 个帖子链接的文本，一次生成 3 个下载任务
- [x] YouTube 交给 Seal：识别到 YouTube 链接（youtube.com/watch、youtu.be、/shorts/）时不解析，提示"YouTube 视频由 Seal 下载"，通过 Android 分享 intent 把链接发给 Seal（包名 com.junkfood.seal）；没安装 Seal 时显示下载指引（F-Droid / GitHub Releases）
  - 验收：已装 Seal 时一键跳转并自动填好链接；没装时显示指引，不报错

## v1.3a 解析器统一

- [x] 把 extension/src 的 TS 解析器打包成一个可注入 WebView 的独立 JS（输入：页面数据；输出：spec 中的统一模型 JSON 或错误模型）
- [x] App 在页面加载完成后注入这个 JS 执行，用它的结果替换 Dart 解析器；保留 Dart 的统一模型和错误模型定义，删除 Dart 的平台解析器；fixture 测试只在 TS 端运行
  - 验收：小红书和 IG 的全部真机测试流程与 v1.1 结果一致；以后新增平台只需要写 TS 一份

## v1.3b 解析器云端热更新

- [x] 发布物：manifest.json（parserVersion、minAppVersion、sha256、Ed25519 签名、各平台启用开关和维护提示、各平台请求头/UA）+ parser.js
- [x] App：启动时检查更新，最多每 6 小时一次；下载后校验签名和哈希，缓存为"最近一个可用版本"；任何一步失败都回退到 App 内置版本；parserVersion 显示在"我的"页和诊断信息中
- [x] 安全：公钥内置在 App 中，签名验证失败时拒绝加载；严禁执行未签名的代码
- [x] 远程开关：平台被关闭时，解析该平台的链接显示维护提示，不发起请求
- [x] 发布流程：GitHub Actions 在推送 parser-v* tag 时运行全部 fixture 测试，通过后打包、签名，发布到 GitHub Releases；私钥只存放在 GitHub Secrets 中
- [x] 插件：遵守 Chrome MV3 规定，不加载远程代码，只拉取 manifest 中的平台开关和请求头配置
  - 验收：故意把一个解析规则改错，发布修复版 parser-v*，手机 App 不重装即可恢复正常；把签名改坏，App 拒绝加载并回退到内置版本

## v1.4 X (Twitter)

- [x] 只使用公开嵌入接口 cdn.syndication.twimg.com/tweet-result；需要登录的推文（敏感内容、锁定账号）返回 LOGIN_REQUIRED，不做 WebView 兜底
- [x] 请求方式参考 Vercel 的 react-tweet（MIT）中 token 的计算方法，以及 yt-dlp 的 Twitter 提取器
- [x] 图片取原图（name=orig），视频取码率最高的 mp4，GIF 作为无声 mp4 视频提取，引用推文只下载被分享推文自身的媒体
- [x] 接口 URL 模板、token 算法参数和请求头纳入 manifest.json 云端热更新配置
- [x] 先采集 fixture（单图、多图、视频、GIF、引用推文、已删除），再写 spec，再实现；按 v1.3 架构只写 TS 一份，支持热更新
  - 验收：全部 X fixture 测试通过；真机上从 X App 分享链接能下载

## v1.5 图库体验

- [x] 本地文件定位：引入 `photo_manager`，按"相册名 + 文件名"在系统相册中定位已保存的文件；历史记录保存每个文件的文件名和保存时间，定位成功后缓存媒体 ID；找不到的文件（用户已在相册中删除）显示"已从相册删除"占位，并提供"重新下载"
    - 验收：下载落盘时持久化相对文件名与保存时间戳；历史页/全屏浏览启动时通过 `photo_manager` 快速定位系统相册文件并缓存媒体 ID；相册手动删除文件后回到 App，该项显示"已从相册删除"占位及[重新下载]按钮，点击可重新下载恢复本地文件并刷新缓存
- [x] 本地缩略图：历史页和解析页"最近"的缩略图全部读取本地文件，不再使用 CDN 地址（CDN 地址带签名，会过期导致裂图）
  - 验收：历史页（瀑布流/列表/全部/创作者）及解析页"最近"缩略图全部优先从本地相册读取；断网冷启动 App，历史卡片与"最近"缩略图均能正常渲染，无任何 CDN 签名过期导致的裂图
- [x] 历史记录操作：点击卡片或列表行 → 打开本地文件的全屏浏览器；"重新解析"→ 重新解析原帖后进入预览页；"打开原帖"→ 用外部浏览器或对应 App 打开
  - 验收：点击卡片或列表行直接调起本地全屏浏览器；点击"重新解析"携带原帖链接发起解析并自动进入预览页；点击"打开原帖"调起系统外部应用或浏览器打开原帖链接
- [x] 统一的全屏浏览器组件：预览页（远程媒体）和历史页（本地文件）共用组件；左右滑动切换，顶部显示"当前 / 总数"；右上角圆形勾选框，选择状态与预览页同步；底部缩略图条可快速跳转，已选中有标记；双指缩放；视频直接播放，Live 图长按播放；下滑关闭；从网格进入时使用 Hero 过渡动画；底部操作提供重新解析、打开原帖、分享
  - 验收：两处共用同一组件实现；手势左右滑动切换顺畅，缩略图条高亮当前项并标记已选项；双指缩放正常；视频切到该页自动直接播放；Live 图默认静态，长按播放实况动效，松手暂停；下滑手势带有阻尼感并触发平滑关闭退出；进出均有顺滑的 Hero 共享元素动画；底部三项操作均可正常响应
- [x] 历史页改版：
  - 三个视图切换：顶部切换"帖子 / 全部 / 创作者"；帖子视图支持瀑布流和列表两种布局，切换后记住用户选择；全部视图将所有帖子的媒体打散平铺成瀑布流；创作者视图按作者聚合，每个作者展示四宫格封面，点击后进入帖子视图并带上该作者筛选
  - 瀑布流卡片：封面保持原始比例；多图帖子右上角显示张数，底部带有轻微叠层阴影；视频显示 ▶ 和时长，Live 图和 GIF 显示角标；底部暗色渐变遮罩上展示平台标签和标题
  - 列表行：点击整行进入全屏浏览；右侧保留"重新解析"和"打开原帖"两个小图标按钮
  - 紧凑工具栏：只用小图标按钮（约 34px，图标 18px），从左到右为搜索、平台筛选、排序、布局切换（布局切换仅在帖子视图显示）；点击后弹出小菜单；有生效中的条件时图标高亮
  - 搜索与排序：搜索展开输入框，按标题和作者过滤；排序支持最新保存、最早保存（按日期分组吸顶）、按类型（图片/视频/Live 图/GIF 分组带数量）、文件最多、按作者（后两者不分组）
  - 筛选与空状态：生效中的平台或作者筛选以可点击清除的小标签显示在视图切换栏右侧；搜索或筛选无结果时显示空状态提示和"清除筛选"按钮
  - 验收：三视图切换平滑；瀑布流/列表布局切换后偏好持久化保存，重启有效；创作者四宫格点击正确跳转并筛选；卡片比例、多图叠层阴影与角标符合规范；工具栏高亮与小菜单交互无误；各排序模式分组与吸顶正确；筛选小标签支持一键清除；空状态支持一键重置筛选
- [x] 历史页的删除与多选：
  - 列表左滑显示删除按钮；瀑布流和"全部"视图不支持左滑以防手势冲突
  - 长按卡片或行进入多选模式：顶部显示"已选 N 项"和全选，底部导航替换为"分享 / 删除"；"全部"视图按单个文件多选，只提供分享
  - 删除确认面板：默认只删除记录，删除后底部提示条支持撤销；可勾选"同时删除相册中的 N 个文件"（默认不勾选），勾选后不支持撤销，通过 `MediaStore.createDeleteRequest` 走系统确认；用户在系统确认中拒绝时，只删除记录并提示
  - 验收：仅列表视图支持左滑露出删除；长按进入多选，顶栏与底栏状态替换完整；"全部"视图多选底栏仅有分享；删除确认面板默认不勾选删文件，点击确认后记录移出并显示 SnackBar [撤销]；勾选删除文件时明确提示不可撤销并调起系统确认，系统授权同意则文件与记录双删，用户拒绝时仅删除记录并 Toast 提示相册文件已保留
- [x] GIF 支持：统一模型中区分 GIF 和普通视频（新增 `gif` 类型，或给视频加 `isGif` 标记，两端解析器和 spec 同步修改）；GIF 自动播放、无限循环、静音、不显示进度条，点击暂停/继续；卡片和缩略图显示 GIF 角标；存到相册时仍保存为 mp4
  - 验收：spec 和 TS/Dart 统一模型已同步支持 GIF；两端解析器能准确输出 GIF 标记；预览页与全屏中 GIF 自动无限循环播放、静音、不显进度条，点击可暂停/继续，左上角显示 GIF 角标；相册落盘为 mp4 且可正常查看播放
- [x] 解析页"最近"改版：保持现有列表样式，只把缩略图改为本地文件，点击进入全屏浏览器，不加左滑和长按
  - 验收：解析首页"最近"维持 3 行紧凑卡片样式；缩略图改为加载本地相册文件；点击直接唤起本地全屏浏览器；无左滑与长按手势

## v1.6 快捷入口

> 交互细节以 [`docs/design/bubble-prototype/`](file:///d:/workspace/IdeaProjects/EasySave/docs/design/bubble-prototype/) 中的截图为准。悬浮球、前台服务用**原生 Kotlin** 实现；解析与下载在**后台 Flutter 引擎**中运行，复用现有 TS 解析器与 `DownloadManager`，不写第二套。

- [x] 分享到 EasySave 后台下载：在系统分享面板选择"EasySave 后台下载"（与打开 App 的分享入口并存），透明 Activity 抽链接 → 从前台启动后台服务 → 立即返回原 App；无链接时提示"没有可解析的链接"
  - 验收：从 IG / X / 浏览器分享一条帖子链接并选"EasySave 后台下载"后，不进入 EasySave、原 App 保持在前台，通知栏出现下载进度，完成后写入相册与历史；分享不含链接的文字时提示"没有可解析的链接"；打开 App 的分享入口行为不变
- [x] 下拉菜单快捷开关（Quick Settings Tile）：label "EasySave 下载"，单色线条图标；点击后经透明页面读剪贴板并直接执行"全部下载"；下载中磁贴显示激活态与进度（Android 10+），空闲恢复；「我的 → 设置 → 快捷入口」提供"添加到控制中心"（Android 13+ 调 `StatusBarManager.requestAddTileService`，Android 12- 显示图文说明）
  - 验收：MIUI 控制中心能编辑并添加"EasySave 下载"磁贴；点击后下拉面板收起并对剪贴板中的链接执行"全部下载"（不打开 App 界面）；在小红书复制链接后走通一次完整下载；下载中磁贴显示进度、空闲时恢复；"添加到控制中心"在 13+ 弹系统确认框、12- 显示说明
- [x] 悬浮球（可选功能，默认关闭，在"我的 → 设置"中开启；开启时引导用户授予"显示在其他应用上层"权限）
  - [x] 权限撤销处理：用户在系统设置里撤销"显示在其他应用上层"权限后，悬浮球自动关闭、设置里的开关同步变为关闭，下次开启时重新引导授权
  - [x] 外观：渐变色圆形按钮（复用主渐变 `#FC494C → #FA662E`），可拖动，松手后吸附到最近的左/右屏幕边缘；闲置时略微透明（如 80% 不透明度）。**不做"剪贴板有链接就显示绿点/晃动"**——Android 10+ 后台拿不到剪贴板变化回调（真机验证），改为**仅点击时读取剪贴板**
  - [x] 点击：读取剪贴板（通过短暂打开一个透明页面读取，读取后立即关闭）；**必须在透明页面获得窗口焦点后再读**（真机在 MIUI 上 `onCreate` 直接读会返回空）；没有支持的链接时提示"先在 App 里复制链接"；有链接时向屏幕内侧展开圆形菜单，带半透明遮罩，点击空白处收起
  - [x] 菜单四项：**全部下载** / **选择下载** / **复制文案** / **打开 EasySave**
    - 全部下载：后台解析并下载，不打开 App 界面；悬浮球显示"已完成 / 总数"与进度环，通知栏同步进度；完成后悬浮球显示 ✓ 并提示保存到哪个相册；点击通知进入历史页
    - 选择下载：**原生 View 面板**（`SelectPanelView`）以 `TYPE_APPLICATION_OVERLAY` 悬浮窗显示（半透明蒙层 + 底部圆角卡片 + 三列缩略图网格，可勾选、带全选/取消全选、加载时 shimmer 呼吸占位、已下载过的图打「已存」角标），确认后转入后台下载，流程同"全部下载"；**不新建第三个引擎**（真机验证：FlutterView 挂 overlay 在 MIUI 上不可靠，故改为原生）
    - 复制文案：后台解析后把标题和正文写入剪贴板，完成后提示
    - 打开 EasySave：唯一启动完整 App 的选项，直接进入该帖子的预览页
  - [x] 下载进行中点击悬浮球：提示当前进度，不重复发起
  - [x] 拖到屏幕底部的关闭区域：关闭悬浮球，并提示可在设置中重新开启
  - [x] 解析失败（需要登录、链接失效等）：悬浮球显示错误状态，点击后打开 App 的对应错误页

## 明确不支持

- **微信视频号**：视频加密，只能在 PC 端通过代理实现，不符合本项目架构，**不要尝试实现**。
- **YouTube**：EasySave 不内置下载，统一交给 Seal 处理（见 v1.2）。原因：需要 JS 运行时和 PO Token，Seal 在 Android 上 2026 年仍频繁出现 403 和机器人验证；内置 yt-dlp 会让 APK 增加数十 MB；违反 YouTube 条款和应用商店政策。**不要尝试内置 yt-dlp 或 youtubedl-android**。
