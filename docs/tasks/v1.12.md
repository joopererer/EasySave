## 第二批：断点续传（build 63 / 64 / 65）

- [x] 后台下载器：优先复用 `background_downloader` 自带的暂停/断点续传能力（`ResumeData`、`Range` 与 `ETag`/`Last-Modified` 校验）。
  - **build 64 针对真机验证未通过的修复**：
    1. 稳定任务 ID：大文件（≥5MB 视频）固定 `taskId = job.key`，确保网络中断、自动重试、用户手动重试、App 被杀恢复时能精准取回插件原生存储的 `ResumeData` 并调用 `FileDownloader().resume()`；
    2. 网络中断等待：将 `SocketException`（如 `Software caused connection abort`）、连接重置、DNS 失败归类为网络中断，即使系统报告在线也进入 `waitingNetwork` 状态，退还 attempt 且保留当前 `progress` 不归零；
    3. 签名地址过期续传：遇到 403/410 时保留临时文件并重新解析帖子获取最新地址，探测确认新地址支持 Range 且 Content-Length 一致后安全续传（否则清理从 0 重下）；
    4. 插件原生 `DownloadTaskRunner.kt` 适配：在 403/410 续传失败分支保留已下载临时文件以供 App 取回。
  - **build 65 针对真机验证未通过的修复（后台下载器响应头大小写敏感与临时文件删除问题）**：
    1. 响应头大小写不敏感：修复 Android 原生 `DownloadTaskRunner.kt` 中直接使用 `connection.headerFields["Accept-Ranges"]` 等大小写敏感查找导致的 CDN（如 Twitter CDN、Cloudflare 返回全小写 `accept-ranges: bytes`、`etag`、`content-range`）无法识别 Range 支持的问题；改为 `connection.getHeaderField(...)`，并确保 `allowPause` 任务被正确识别为支持续传；
    2. 修复连接中断时临时文件被误删：当 `serverAcceptsRanges` 为 false 时原生 `prepResumeAfterFailure` 会进入 else 分支执行 `deleteTempFile()` 导致部分下载文件被清除；修复后正确保留临时文件并生成 `ResumeData`；
    3. 修复原生通道 `resumeData` 回调返回值：Android `QueueService` 中等待 MethodChannel 调用返回 true，而 Dart 端此前返回 null 导致判断失败并退回到原生未投递暂存区；现已正确返回 true，并在 `NativeDownloader` 中提供 `getResumeData` 兜底拉取；
    4. 消除 `reason=status_200` 误判：删除根据进度回落（`progress > 0.1 && progress < 0.05`）推测 status_200 的错误逻辑；精准输出诊断日志与实际原因（`no_resume_data`, `tempfile_missing`, `taskid_mismatch`, `status_200`, `range_accepted` 等）；
    5. 补充全链路诊断日志：在失败回调、首次响应、续传恢复点记录结构化诊断日志，便于真机排查。
- [x] App 内直接下载（session 传输，如 TikTok）：实现 `Range` 续传，并通过 `If-Range`（ETag 或 Last-Modified）确保服务端文件未变更。
- [x] 续传判定与完整性：
  - 支持 Range（206）且校验值一致从已有字节断点续传；
  - 返回 200（不支持 Range）、校验值变化、或已有分块损坏时丢弃已下载部分重新下载；
  - 续传返回 403/410 视为候选失效，走重新解析续传或重试流程；
  - 下载完成后校验总大小与 Content-Length 一致并验证文件类型。
- [x] 阈值与私有目录存储：≥ 5MB 启用续传（低于 5MB 维持失败重下，避免额外握手与存储碎片开销）；未完成的临时部分文件存私有目录，在取消、批次结束或超时清理。
- [x] 请求头白名单：在 Dart `MediaRequestPolicy` 与原生 `MediaPolicyRedirects.kt`、`NativeMediaRequest.kt` 中同步放行 `If-Range`。
- [x] 结构化日志：`[V16DL] resume index=… role=… from_bytes=… total=… result=resumed|restart reason=no_range|validator_changed|status_200|expired|…`，不记录任何敏感参数。
