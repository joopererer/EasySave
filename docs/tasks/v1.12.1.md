# v1.12.1 任务文档

## 1. 背景与目标

在 v1.12.0 正式发布后，根据真机测试与用户体验反馈，梳理出两个状态与判定不一致问题，以及历史页列表浏览体验的优化需求：

1. **下载状态文案统一（Item A）**：存储空间不足时，解析预览页底部保存弹窗（「正在保存 0/1」）错误显示为「已暂停」，而历史卡片与下载队列显示为「空间不足」。各展示面存在自写状态映射逻辑，文案与优先级未完全收拢。
2. **历史页 Live 标记对齐与修复（Item B）**：部分通过备份恢复或相册扫描恢复的小红书帖子，历史卡片未显示 Live 标记，但进入大图浏览后能正常识别为实况并长按播放。两处对「是否实况」的判定逻辑源存在分歧，且导入链路未补写实况标记。
3. **历史页「返回顶部」按钮（Item C）**：长列表向下浏览时缺乏快速回顶手段，需提供平滑且在超长距离下能快速归位的返回顶部按钮，且不与既有浮动元素重叠。
4. **历史页「新内容提示」与高亮（Item D）**：用户在历史页浏览旧内容时，后台新完成的下载不应突兀打乱滚动位置，应以非侵入式顶部胶囊条提示，并在回到顶部时提供清晰的新卡片高亮反馈。

目标版本：`1.12.1+80`。

## 2. 修改内容与实现细节

### 2.1 Item A: 下载状态文案统一
- **统一服务**：新建 `app/lib/services/download_status_display.dart`，提供唯一的 `resolveDownloadStatus(DownloadStatusInput input)` 函数，输入下载状态与阶段，输出对应的统一展示文案（`label`）与图标（`icon`）。
- **接入展示面**：历史卡片（`history_card.dart`）、下载队列（`download_queue_sheet.dart`）、解析预览页底部保存弹窗（`parse_preview_sheet.dart`）、悬浮球（`bubble_service.dart`）、系统通知（`notification_service.dart`）全部改用该函数，彻底删除各处的自写文案逻辑。
- **状态优先级**：与 build 75 保持一致：
  $$\text{空间不足} > \text{用户手动暂停} > \text{下载中断 / 等待网络 / 自动重试} > \text{收尾与保存阶段} > \text{最终失败 / 取消} > \text{正常下载中}$$
- **保存弹窗修复**：解析预览页底部保存弹窗在存储不足时统一显示为「空间不足」，消除此前的「已暂停」误导文案。

### 2.2 Item B: 历史页 Live 标记对齐与启动修复
- **根因差异分析**：
  - 历史卡片此前依赖数据表中文件的扩展信息或记录级标记，通过备份恢复或相册扫描恢复的历史记录因没有或未补写 `pairId`，导致卡片判定非实况；
  - 大图浏览通过 `pairSavedMedia(record.savedFiles)` 实时扫描相册文件与配对关系，因此能够动态识别实况。
- **逻辑对齐**：卡片层改为与大图浏览使用完全一致的 `pairSavedMedia(record.savedFiles)` 配对逻辑，只要包含有效配对即展示 Live 标记。
- **写入补齐**：在相册扫描恢复（`history_rebuild_service.dart`）与备份恢复（`backup_service.dart`）构建记录时，为实况成对的图片与视频文件行补写配对标识（`pairId`）。
- **启动单次修复**：新增 `LiveBadgeRepairService`，在 App 初始化（`main.dart`）时扫描历史数据库中缺少 `pairId` 但实际成对的存量记录，补齐后更新数据库，日志输出 `live_badge_repair posts=<n> pairs=<n>`；利用 `SharedPreferences` 标记，确保全局仅执行一次。
- **诊断日志**：打开全屏大图浏览时输出脱敏诊断日志：
  `[LiveBadge] post=<postId> card=<yes|no> viewer=<yes|no>`，用于真机快速确认两端判定严格一致。

### 2.3 Item C: 历史页「返回顶部」按钮
- **显示与隐藏阈值**：
  - 纵向滚动距离超过 2 个屏幕高度（`offset > 2 * viewportHeight`）时，右下角淡入返回顶部按钮；
  - 回到 1 个屏幕高度以内（`offset <= viewportHeight`）时淡出隐藏。
- **界面与无障碍**：
  - 位于右下角独立悬浮位置（`bottom: 20, right: 16`），尺寸为 $44\times 44\text{dp}$ 圆形按钮，带有平滑阴影与图标；
  - 与悬浮球和下载队列入口垂直错开，在系统大字号（TextScaler 1.3）与不同分辨率下无重叠或布局溢出。
- **平滑滚动与长距离快速跳转**：
  - 常规距离点击直接平滑滚动至顶部；
  - 滚动距离超长（超过 20 屏，`offset > 20 * viewportHeight`）时，先瞬时快速跳跃至接近顶部（约 2 屏处），再执行平滑滚动归位，保证总耗时严格控制在 500ms 以内。
- **规则隔离**：不改变 v1.11 确定的筛选或排序切换时的滚动保留行为。

### 2.4 Item D: 历史页「新内容提示」与高亮
- **新内容累积与浮动胶囊条**：
  - 当列表处于非顶部（`offset > viewportHeight`）时，后台完成的新下载帖子不强行打扰当前浏览位置，而是将帖子 ID 收集至 `_pendingNewPostIds`，并在历史页顶部居中显示淡入胶囊条「有 N 条新内容 ↑」；
  - 当列表处于顶部（`offset <= viewportHeight`）时，新记录直接平滑刷新进入列表，不展示提示条。
- **点击回顶与手动回顶反馈**：
  - 点击胶囊条或手动滑动回顶（`offset <= 10.0`）时，提示条淡出隐藏；
  - 新加入的卡片外围展示 $2\text{dp}$ 主题色微光高亮边框，持续 1.5 秒后平滑清除。
- **多视图支持**：在瀑布流模式、列表模式与全部媒体（All Media）模式下均支持提示条与卡片高亮联动。

## 3. 测试覆盖与验证要点

### 3.1 自动化测试覆盖
- `app/test/v1121_download_status_consistency_test.dart`：
  - 验证 `resolveDownloadStatus` 在五处（卡片、队列、保存弹窗、悬浮球、通知）的状态文案与图标映射严格一致；
  - 覆盖 `insufficientStorage` 状态在解析预览页保存弹窗中正确展示为「空间不足」。
- `app/test/v1121_live_badge_test.dart`：
  - 验证相册扫描与备份恢复后生成的历史记录能正确展示 Live 标记；
  - 验证 `LiveBadgeRepairService` 仅单次执行修复并输出指定格式日志；
  - 验证进入大图浏览时输出 `[LiveBadge] post=... card=yes viewer=yes`。
- `app/test/v1121_scroll_to_top_test.dart`：
  - 验证超过 2 屏出现、小于 1 屏消失的阈值行为；
  - 验证点击回顶以及超过 20 屏时的快跳加平滑滚动总时长；
  - 验证 TextScaler 1.3 字体下与悬浮球无重叠。
- `app/test/v1121_new_content_indicator_test.dart`：
  - 验证滚动远离顶部时新内容累积与「有 N 条新内容 ↑」提示条；
  - 验证在顶部时新内容直接入队不显示提示条；
  - 验证点击提示条平滑滚回顶部并触发新卡片高亮边框；
  - 验证手动滚回顶部时清除提示并触发高亮边框；
  - 验证高亮边框在 1.5 秒后自动清除；
  - 验证全部媒体模式与单列模式兼容。

### 3.2 兼容性回归测试
