## 2. Release signing

- `app/android/app/build.gradle.kts` reads `storeFile`, `storePassword`, `keyAlias`,
  `keyPassword` (and optional `storeType`) from
  `%USERPROFILE%\.easysave\key.properties`; the path can be overridden with the
  `EASYSAVE_KEY_PROPERTIES` environment variable.
- The release build type uses that configuration. If the file, any field or the keystore
  itself is missing, the `requireReleaseSigning` task (wired into `preReleaseBuild`)
  fails the release build with an explicit message. There is no silent fallback to the
  debug keystore.
- The properties file and the keystore are never opened, printed or copied by tooling in
  this repo; only Gradle reads them at build time. No value from them appears here.
- `*.jks`, `*.keystore` and `key.properties` are ignored in `.gitignore`.

**Rule for every future round:** any APK handed to the user for installation is a
release build signed with the release key (`flutter build apk --release`), so each new
build installs over the previous one without uninstalling. Debug-signed APKs are never
delivered. See `docs/release-signing.md`.

## 5. Signing key change and upgrade steps

This is the first release signed with the new key, so it cannot be installed over an
older EasySave build. Users must:

1. Export a backup from the old version.
2. Uninstall the old version.
3. Install this APK.
4. Restore the backup.
5. Re-authorize permissions (gallery, floating overlay, notifications) and log in again.
