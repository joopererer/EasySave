## 1. 验证一：前台服务内独立 Flutter 引擎的后台解析

**目标**：不打开任何 Activity，在 Foreground Service 里跑一个独立 `FlutterEngine`，用现有 `parsePostOutcome` 解析 XHS / IG / X 三个链接，并确认 `HeadlessInAppWebView` 无 Activity 可用、且能读到 App 内登录后的 cookie。

### 结论：**有条件可行** ✅（可编译、符合插件实现；需真机确认同一台设备上的运行结果）

**依据（代码层面）**
- `flutter_inappwebview_android` 的 `HeadlessInAppWebViewManager.run()`：
  `Context context = plugin.activity; if (context == null) context = plugin.applicationContext;`
  → **Headless 模式本就不依赖 Activity**，用 Application Context 即可。
- `HeadlessInAppWebView` 不是 Flutter 平台视图（PlatformView），而是**原生持有一个游离的 `WebView`**、通过 `MethodChannel` 通信。因此**不需要 FlutterView 挂载、不需要 Activity**，只要引擎在跑、插件已注册即可。
- 引擎创建：`FlutterEngine(context, null, true)`（`automaticallyRegisterPlugins=true` 自动跑 `GeneratedPluginRegistrant`），再 `executeDartEntrypoint(DartEntrypoint(findAppBundlePath(), "backgroundMain"))`。已验证该 API 与入口点保留（`@pragma('vm:entry-point')`）。
- **Cookie 共享**：Android 端 flutter_inappwebview 的 `CookieManager` 底层就是进程级的 `android.webkit.CookieManager` 单例；第二引擎（**同进程**）读到的就是主 App 登录 WebView 写入的同一份 cookie。`sharedCookiesEnabled: true` 还会把 cookie 同步到原生 HTTP 栈（X/IG 的 HTTP 请求会带上）。
- 已通过 `flutter build apk --release` 编译验证（55.6MB），Kotlin/Dart 均无误。

**需要真机确认的点（探针会打印）**
- `BG isolate up` / `ParserManager ready` → 引擎与解析器在无 Activity 下正常初始化；
- `COOKIES xhs=? ig=? x=? len=? (NON-EMPTY/EMPTY)` → 与主 App 登录状态一致即为"cookie 共享成功"；
- `PARSE OK/FAIL[...]` → 三条链接在后台引擎内的实际解析结果。

**已知问题 / 风险**
- **必须与主 App 同进程**（默认即可）。若将来把后台引擎放到 `:remote` 独立进程，`android.webkit.CookieManager` 单例不再共享，cookie 需要落盘传递。
- 个别 OEM ROM 对"应用上下文创建 WebView"较苛刻，可能失败 → 备选：在 Service 里挂一个 **1×1 透明 `FlutterView`** 作为宿主（`flutter_background_service` 的做法）后再跑 Headless WebView。
- 多引擎会占用额外内存（一个引擎约十几~几十 MB），解析结束应及时 `engine.destroy()`。
- XHS 的解析本身可能因未登录/风控返回 `LOGIN_REQUIRED`，这属于**功能**结果而非**引擎**问题；验证时用已登录账号。

## 2. 验证二：透明 Activity 读取剪贴板

**目标**：点悬浮球后，短暂启动一个透明 Activity 读剪贴板，读完立即关闭；确认 Android 10+ 能读到内容，且不把当前 App（如小红书）退到后台、不闪烁。

### 结论：**有条件可行** ✅（透明 Activity + 无动画即可；代价是宿主会收到一次 `onPause`）

**依据**
- Android 10+ 限制"只有**持有焦点的前台应用**能读剪贴板"。一个**可获得焦点**的透明 Activity 处于前台，因此可读。探针未设置 `FLAG_NOT_FOCUSABLE`（否则会因无焦点读不到）。
- 声明 `android:theme="@android:style/Theme.Translucent.NoTitleBar"` + `noHistory` + `taskAffinity=""` + `excludeFromRecents`，代码里 `overridePendingTransition(0,0)`、`window.setBackgroundDrawable(TRANSPARENT)` → **无可见窗口、无转场动画**，视觉上不闪烁。
- 因是"透明覆盖"，小红书界面仍可见；Activity 读完 `finish()` 立即消失。

**需要真机确认的点**
- `CLIPBOARD=...` 是否打印出内容（Android 10/13/14）；
- 视觉上是否闪烁、小红书是否出现明显重绘/丢失输入焦点；Android 12+ 会出现系统"已从 X 粘贴"提示（系统行为，无法去除）。

**已知问题 / 风险**
- 启动 Activity 会让宿主 App 立即 `onPause`（不是 `onStop`/被杀），且我们的透明页在它之上。**严格意义上宿主进入了 paused 态**；对绝大多数 App 无影响，但这是本方案最大的不确定点，需真机确认。
- 若某些场景仍感突兀，备选：
  1. 用**可获焦点的 overlay 窗口**（`TYPE_APPLICATION_OVERLAY` + 临时申请焦点）读剪贴板，完全不启动 Activity；
  2. 借助**系统的文本选择菜单 / 分享**（见实现方案的 PROCESS_TEXT 与 Tile 入口），用户主动触发时天然在前台，读取更自然。
- `ClipboardManager.getPrimaryClip` 在新版本会返回"敏感内容"标记；读取需处理 `ClipDescription` 的敏感 flag。

## 3. 验证三：悬浮窗里的"选择下载"面板方案对比

**目标**：比较「原生 Kotlin 绘制」与「FlutterView 挂到悬浮窗」两种方案，给出推荐。

### 对比

| 维度 | 原生 Kotlin 绘制 | FlutterView 挂到悬浮窗 |
|---|---|---|
| 内存 | **低**：仅一个 overlay 窗口，无额外引擎 | 高：需**第二个 FlutterEngine** + FlutterView（十几~几十 MB） |
| 开发量 | 中高：面板 UI（九宫格/勾选/全选/按钮）要手写；缩略图要接图片库并**手动附带 Referer/UA 头**（XHS/IG/X CDN 必需）；风格 token 要手工对齐 | **低**：直接复用现有选择面板与 `CoverImage`（含 Referer 逻辑）、复用主题 |
| 风格一致 | 中：要按 token 逐项还原，易漂移 | **高**：与 App 内完全一致 |
| 技术风险 | 低：单窗口，成熟做法 | 中高：FlutterView 挂 `TYPE_APPLICATION_OVERLAY` 窗口 + 输入分发，引擎生命周期管理复杂 |
| 复用现有代码 | 无（重写面板） | 高（解析/下载/UI 都能复用） |

### 结论：**两者都可行；推荐"混合"**

- **悬浮球：原生 Kotlin**（常驻、要轻量、可拖动吸附、闲置半透明）——内存与稳定性优先。
- **选择下载面板：FlutterView + 按需引擎**（弹出时才创建引擎、关闭即销毁），理由是它**复用现有九宫格选择面板与带 Referer 的缩略图管线**，开发量与风格一致性两项最优；面板是**临时**弹出的，内存峰值可接受。
- 若希望 v1.6 首版**最省事、最稳**，也可先全原生（面板用 Coil/OkHttp 加 Referer 加载缩略图），后续再评估 FlutterView。**本方案默认采用混合方案。**

> 验证三当前只落地了**原生面板探针**（`OverlayService.togglePanel()`），用于确认"原生 overlay 面板 + 圆角/按钮/九宫格"在真机可正常显示、可点击。FlutterView 方案作为推荐项在实现阶段落地。

## 4. 基于结论的完整实现方案（覆盖 roadmap v1.6 全部）

### 4.1 架构总览

```
┌─────────────── 三个入口 ───────────────┐
│ 悬浮球(BubbleService, 原生)            │
│ Quick Settings Tile (原生 TileService) │
│ PROCESS_TEXT (透明 Activity 收文本)    │
└───────────────┬────────────────────────┘
                │ 统一 → "解析+下载" 任务
                ▼
      前台服务 HostService（原生，FGS）
        ├─ 独立 FlutterEngine（后台 isolate）
        │    ├─ 解析：复用 parse_service（HeadlessInAppWebView）
        │    └─ 下载：复用 DownloadManager
        ├─ MethodChannel 进度/结果上报 → 更新悬浮球 + 通知
        └─ 可选：FlutterView（仅选择面板时按需创建）
```

**核心原则**：三个入口**只负责"拿链接 + 触发"**，解析与下载**全部复用**现有 `parsePostOutcome` 与 `DownloadManager`，不写第二套。所有产物写入历史（HistoryDb），与 App 内一致。

### 4.2 后台任务 Host（对应验证 1）

- `HostService`（Foreground Service，`foregroundServiceType"dataSync"`）持有**唯一**后台 `FlutterEngine`（复用验证 1 的创建方式）。
- 通过 `MethodChannel("easysave/bgtask")` 暴露：`submit(urls, mode)`（mode = all / select / caption / open）、进度回调、结果回调。
- 解析/下载在 Dart 侧直接调用 `parsePostOutcome` 和 `DownloadManager.instance.startBatch`，进度经 `DownloadManager` 监听转发到原生。
- 结束后按需销毁引擎；进程内与主 App 共享 cookie 与 SQflite/HistoryDb。

### 4.3 悬浮球（原生，BubbleService）

- **开关与授权**：我的→设置新增"悬浮球"开关（默认关）；开启时若 `!Settings.canDrawOverlays()` → 跳 `ACTION_MANAGE_OVERLAY_PERMISSION`；返回后复查。
- **权限撤销联动**：BubbleService 监听 `ACTION_MANAGE_OVERLAY_PERMISSION` 变化 / 每次 `onStartCommand` 与前台切换时 `Settings.canDrawOverlays()` 复查；为 false 时自我 `stopSelf()` 并通知 Dart 把设置开关置灰（持久化）。下次开启重新引导。
- **外观**：渐变圆（`#FC494C→#FA662E`）、可拖动、松手吸附最近左右边缘、闲置 `alpha≈0.8`。
- **绿点 + 晃动**：注册 `OnPrimaryClipChangedListener`；剪贴板出现可解析链接时显示绿点并播放一次晃动动画（`ObjectAnimator`）。
- **点击**：先读剪贴板（见 4.5），无链接 → Toast"先在 App 里复制链接"；有链接 → 向内侧展开圆形菜单（原生 overlay，四项：全部下载 / 选择下载 / 复制文案 / 打开 EasySave），带半透明遮罩，点空白收起。
- **进度态**：下载中显示"已完成/总数"+ 环（`ProgressBar` 环形）→ 与通知栏同步；下载中点击只弹 Toast 报进度，不重复提交。
- **完成态**：显示 ✓ + Toast"已保存到《相册名》"；点击通知进历史页。
- **错误态**：解析失败红底感叹号，点击用 `Intent` 打开 App 并从错误码进入对应错误页（复用 ParseFailure.code）。
- **关闭区域**：拖动到屏幕底部中央的关闭圆（红色 ✕，拖动时出现）松手即关闭，Toast"可在设置中重新开启"。

### 4.4 快捷开关（Quick Settings Tile）

- `EasySaveTileService`（原生）：
  - `onClick()`：读剪贴板（同样用透明 Activity 或 focusable overlay）→ 有链接则提交 `mode=all` 给 HostService，无链接则 Toast。
  - `onStartListening()` 更新磁贴状态（未登录/空闲/进行中）。
- 磁贴图标与"我的→设置"里加一个"添加到快捷设置"的说明（引导用户用系统面板添加）。

### 4.5 剪贴板读取（统一下沉）

- 三个入口统一走 `ClipboardReader`：透明、无动画 Activity（复用验证 2），`Intent` 带回文本；调用方拿到文本后做**可解析链接判定**（复用 `platformFromUrl`）。
- 处理 Android 10+ 焦点限制与 Android 12+ 敏感内容标记。

### 4.6 文字选择菜单（PROCESS_TEXT）

- 新增 `ProcessTextActivity`：`intent-filter` 声明 `android.intent.action.PROCESS_TEXT`，`android:label` 用"EasySave 下载"，`android:exported="true"`。
- 收到 `EXTRA_PROCESS_TEXT` → 抽取链接 → 提交 `mode=all` → Toast，**不显示界面**（透明 Activity）。

### 4.7 下载链路复用

- "全部下载"：`parsePostOutcome` → `DownloadManager.startBatch(post, 全部 index)`。
- "选择下载"：解析后弹选择面板（见 4.9）→ 确认后 `startBatch` 选中项。
- "复制文案"：解析后 `ClipboardManager.setPrimaryClip(标题+"\n"+正文)`，Toast。
- "打开 EasySave"：`Intent` 启动 `MainActivity` 并携带预览所需参数，`MainActivity` 跳到预览页。
- 所有批次终态写入 HistoryDb（现有逻辑已支持"App 被杀也补写"）。

### 4.8 前台服务类型与合规（Android 14）

- `HostService` / `BubbleService` 声明 `android:foregroundServiceType`：解析+下载用 **`dataSync`**；悬浮球若判定为特殊用途用 **`specialUse`** + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`。
- 补 `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC`（已具备）/ 视需要 `FOREGROUND_SERVICE_SPECIAL_USE`。
- 通知栏常驻前台通知，展示进度。

### 4.9 选择下载面板（推荐 FlutterView，见验证 3）

- 弹出时按需创建 `FlutterEngine(backgroundPanel)` + `FlutterView`，加入 `TYPE_APPLICATION_OVERLAY` 窗口（居中，圆角卡片）。
- 面板 UI 复用现有九宫格 + 勾选 + 全选 + "下载选中(N)"。
- 关闭即销毁引擎与窗口。

### 4.10 "我的 → 设置"改动

- 新增分组"快捷入口"：悬浮球开关（含授权引导与撤销联动）、"添加到快捷设置"说明项、剪贴板读取说明。

## 6. 验证结论速览

| 验证 | 结论 | 关键条件 / 风险 |
|---|---|---|
| 1 后台解析 | **有条件可行** | 需与主 App **同进程**；个别 OEM 需 1×1 FlutterView 宿主兜底；真机确认 cookie 与解析结果 |
| 2 透明 Activity 读剪贴板 | **有条件可行** | 透明 + 无动画不闪烁、可读；宿主会 `onPause`（非后台被杀）；备选 focusable overlay |
| 3 选择面板方案 | **两者皆可行，推荐混合** | 悬浮球原生；选择面板 FlutterView（复用 UI/图片管线），首版也可先全原生 |
