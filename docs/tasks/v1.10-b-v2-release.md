## 真机验证步骤（待用户执行）

1. 使用原 **1.10.0+24**，进入“我的”页底部的“解析器版本”。更新前应为 `1.4.5 (内置)`；若此前已成功更新，可能已显示云端版本。
2. 点击该行右侧刷新按钮（tooltip“检查更新”）。这是强制检查，会绕过自动每日检查间隔和条件请求。自动检查在前台启动时触发，最多每日一次，不能用它判断按钮是否工作。
3. 成功后该行必须显示 **`1.4.7 (云端)`**。“云端”即已验证并激活的热更新来源；仅出现“解析器已更新到最新版本”提示条不足以证明版本生效。失败也可能显示“当前已是最新解析器”，因此以版本和来源为准。
4. 用一个尚未解析过的帖子链接执行解析，避免 `ParseCache` 的旧结果掩盖新脚本使用。正常可观察 `[ParseCache] event=miss/store` 和实际加载时的 `[ParseWebView]`；重复打开可能只出现 cache hit。解析逻辑未变，结果应与 1.4.5 一致。
5. build 24 **没有成功热更新专用的持久日志标签**，不应期待并不存在的 `[ParserUpdate] success`。失败时控制台/logcat 可能出现 `ParserManager: v2 update rejected; retaining current release`、`ParserManager: local v2 bundle unavailable`；这些是 debugPrint，不保证出现在 App 导出的 DevLog 中。`[ParseMismatch]` 是异常诊断，正常情况不应要求出现。
6. 彻底退出 App 后重新打开，不再点击更新，“解析器版本”仍应为 **`1.4.7 (云端)`**，再解析一个新链接。启动与每次使用会重新验证本地清单和 parser，而非仅信任内存状态。
7. 若仍显示内置，保留当前版本/来源、提示及可导出的诊断日志，稍后重试以排除 GitHub CDN 缓存或网络失败；不要卸载、清数据、读取私有目录或修改本地更新状态。

上述是真机复测步骤，不表示已经真机验证。
