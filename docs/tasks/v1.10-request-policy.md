# 2b-2 请求策略：第 1 步域名依据与接入交接

本表的 `mediaHosts` 都启用子域名匹配：请求主机等于列出的域名，或以 `.` 加该域名结尾。它不允许 `tiktok.com.evil.com` 这类前缀伪装。`cookieDomains` 只授权从实际媒体 URL 向系统 CookieManager 查询；清单以外的域名不能由单项资源扩权。当前信任边界是签名清单的精确声明与域名边界匹配，没有引入公共后缀数据库；`com`、`co.uk` 等未声明目标的拒绝用例已覆盖。

小红书、Instagram、X 的 `cookieDomains` 均为空。TikTok 仅为 `tiktok.com`；图片 CDN 不继承该 Cookie 授权。域名证据采集只读取本地资料的主机名和字段路径，未把带签名的 URL、查询参数或 Cookie 写进本文或测试输出。TikTok 既有脱敏 fixture 使用 `media.example` 占位，测试先确认占位域被拒绝，再只替换主机为上述有证据的域，保持路径、查询参数、资源角色和要求不变，以验证完整 fixture 语料。

第 1 步提供 `MediaRequestPolicy`、逐资源 `resources` 声明、旧字段适配、每跳独立授权和 TikTok 已知 `expire`/`x-expires` 的 TS 解析。消费者在第 2 步必须关闭自动重定向，每跳调用 `redirect`，仅使用该跳的 `wireHeaders`；所有下载、预览、分享及 Kotlin 原生面板接入后，才能移除现存平台 Referer 表、旧 Cookie 取法和 `session_media_download.dart` 的 URL 过期猜测。当前生产请求路径仍沿用原逻辑；第 1 步只建立并验证策略核心和解析结果契约。原生面板不得读 Cookie，所需资源应显示占位并引导 App 内预览。

## 第 2 步：消费者接入

下载任务快照现保存每个候选资源的无 Cookie 声明。后台任务只接收已授权且不携带 Cookie 的请求头，并将清单 `mediaHosts` 写入任务元数据；随项目锁定的 `background_downloader` 9.5.9 源码副本在 Android 侧再次验证主机与请求头、关闭自动重定向、逐跳解析后再下载。探测连接与实际连接分开，保留插件在实际连接上设置断点续传 `Range` 的时机；若实际响应又发生跳转则拒绝。旧排队任务缺少策略元数据时拒绝并提示重新解析，不沿用不受控的旧传输。

会话下载每跳调用 Dart 策略重新授权并按该跳实际媒体地址读取 Cookie；Cookie 仅在内存请求头中存在，403/声明过期不自动重试，取消与中断状态沿用原语义。图片预览和分享使用同一个关闭自动重定向的受控 HTTP 函数。视频播放器自身不提供逐跳校验回调，因此先经该函数下载到临时缓存文件，再交给本地播放器；真机应重点检查首次画面等待时间、临时空间和大视频体验。旧媒体 URL 参数过期猜测已移除。

原生选择面板只接收 Dart 验证后的无 Cookie 声明，Kotlin 对初始 URL、头和每个跳转再次校验；需要 Cookie 的资源不发起网络请求，显示“请在 App 内预览”的占位与打开 App 的入口。无需 Cookie 的图片按声明的头读取；视频先受控下载到临时文件播放。拒绝时向后台 Dart 引擎传固定错误码和主机名，写入 DevLog，界面显示“该资源地址不在允许范围内”。

第 2 步最终硬编码复查见 [v1.10-audit/README.md](v1.10-audit/README.md)。媒体请求策略的平台分支已清空；扩展静态权限和签名 parser 算法按各自边界保留。App 测试版本为 `1.10.0+10`。
